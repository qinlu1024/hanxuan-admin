# 晗煊后台管理系统 · 容器化部署运维文档

> 版本：v1.0　　更新日期：2026-10-11
> 适用部署形态：Docker Compose 全链路编排（PostgreSQL + Spring Boot 后端 + Nginx 前端）

## 1. 系统架构

```
                          用户浏览器
                              │  https://<服务器IP>  (端口 443，自签名证书)
                              │  http://(端口 80) → 301 强制跳转 https
                              ▼
                ┌──────────────────────────┐
                │  hanxuan-admin-web       │  Nginx 1.27 + TLS
                │  前端静态资源 + /api 反代  │
                └──────────────────────────┘
                              │  http://backend:8080  (容器内网 hanxuan-net)
                              ▼
                ┌──────────────────────────┐
                │  hanxuan-admin-backend   │  Spring Boot 3.2 / JRE 17
                │  业务 API / Sa-Token 鉴权 │
                └──────────────────────────┘
                              │  jdbc:postgresql://postgres:5432
                              ▼
                ┌──────────────────────────┐
                │  hanxuan-postgres        │  PostgreSQL 16
                └──────────────────────────┘
```

| 容器名 | 镜像 | 角色 | 端口映射 |
|---|---|---|---|
| hanxuan-admin-web | hanxuan-admin-web:2.0 | Nginx 静态站点 + 接口反代 + TLS 终结 | `80:80`、`443:443` |
| hanxuan-admin-backend | hanxuan-admin-backend:1.0 | Spring Boot 应用（context-path: /api） | `127.0.0.1:8080:8080` |
| hanxuan-postgres | postgres:16-bookworm | 数据库 | `127.0.0.1:5432:5432` |

所有容器均配置 `restart: unless-stopped`，Docker 服务重启或服务器重启后会自动拉起。

## 4. 快速部署（首次）

> 以下命令以 Linux 路径 `/opt/hanxuan` 为例；**当前 Windows 环境**对应后端目录 `d:\Workspace\Ai\hanxuan-admin`、前端目录 `d:\Workspace\Ai\hanxuan-admin-web`，命令在 PowerShell 中执行、路径相应替换即可。

### 4.1 准备源码目录

确保服务器上存在如下同级结构（compose 通过 `../hanxuan-admin-web` 引用前端）：

```
/opt/hanxuan/
├── hanxuan-admin/          # 后端工程（compose 所在目录）
│   ├── docker-compose.yml
│   ├── Dockerfile
│   └── src/...
└── hanxuan-admin-web/      # 前端工程
    ├── Dockerfile
    ├── nginx.conf
    └── src/...
```

> 注意：`.env` 与 `certs/` 均在 `.gitignore` 中，**不会随仓库克隆**，必须按下面 4.2、4.3 手动创建，否则首次启动会用空 JWT 密钥且前端容器因找不到证书而退出。

### 4.2 创建 .env（数据库密码与 JWT 密钥，必需）

在后端工程根目录创建 `.env`（与 `docker-compose.yml` 同级）：

```bash
cd /opt/hanxuan/hanxuan-admin

# 生成随机强密码与 64 位随机 JWT 密钥并写入 .env（Linux）
echo "DB_NAME=hanxuan_admin"                       >  .env
echo "DB_USERNAME=postgres"                        >> .env
echo "DB_PASSWORD=$(openssl rand -base64 24 | tr -dc 'A-Za-z0-9' | head -c 24)" >> .env
echo "HANXUAN_JWT_SECRET=$(openssl rand -hex 32)"  >> .env
```

Windows（PowerShell，无 openssl 时用 .NET 生成）：

```powershell
cd d:\Workspace\Ai\hanxuan-admin
$dbChars = 'ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnpqrstuvwxyz23456789'.ToCharArray()
$hexChars = '0123456789abcdef'.ToCharArray()
$dbPwd = -join (1..24 | ForEach-Object { $dbChars | Get-Random })
$jwt = -join (1..64 | ForEach-Object { $hexChars | Get-Random })
@"
DB_NAME=hanxuan_admin
DB_USERNAME=postgres
DB_PASSWORD=$dbPwd
HANXUAN_JWT_SECRET=$jwt
"@ | Set-Content -Encoding UTF8 .env
```

> 当前环境已有配置好的 `.env`，**无需重建**；以下仅适用于全新机器。

### 4.3 生成自签名证书（必需）

在后端工程根目录用临时 alpine 容器生成（会自动联网拉取 alpine 镜像）。把 `IP:192.168.1.171`、主机名替换为本机实际值：

```bash
mkdir -p certs
docker run --rm -v "$PWD/certs:/certs" alpine:3.20 sh -c "
  apk add --no-cache openssl >/dev/null 2>&1 &&
  openssl req -x509 -newkey rsa:2048 -nodes
  -keyout /certs/nginx.key -out /certs/nginx.crt -days 3650
  -subj '/C=CN/O=Hanxuan/CN=hanxuan-admin'
  -addext 'subjectAltName=DNS:localhost,IP:127.0.0.1,IP:192.168.1.171'"
```

Windows（PowerShell，注意用 `${PWD}` 挂载当前目录）：

```powershell
cd d:\Workspace\Ai\hanxuan-admin
New-Item -ItemType Directory -Force -Path .\certs | Out-Null
docker run --rm -v "${PWD}/certs:/certs" alpine:3.20 sh -c "
  apk add --no-cache openssl >/dev/null 2>&1 &&
  openssl req -x509 -newkey rsa:2048 -nodes
  -keyout /certs/nginx.key -out /certs/nginx.crt -days 3650
  -subj '/C=CN/O=Hanxuan/CN=hanxuan-admin'
  -addext 'subjectAltName=DNS:localhost,DNS:DESKTOP-64UNE1F,IP:127.0.0.1,IP:192.168.1.171'"
```

> 证书详细说明、IP 变更重签、替换为受信任证书见第 11 章。

### 4.4 一键构建并启动

完成 4.2、4.3 后，在后端工程根目录执行：

```bash
docker compose up -d --build
```

首次执行会：构建后端镜像（拉 Maven 依赖，约 3~6 分钟）、构建前端镜像（npm ci + build，约 1~3 分钟）、拉取 PostgreSQL / alpine 镜像、创建网络与数据卷，并按健康检查顺序启动。

### 4.5 查看启动状态

```bash
docker compose ps
```

预期输出三行，其中 postgres 状态为 `healthy`，backend / web 为 `Up`。
若 frontend 反复 `Restarting`，多为证书未生成或挂载路径不对（返回 4.3 检查）。

### 4.6 验证

| 验证项 | 命令 / 地址 | 预期 |
|---|---|---|
| 后端健康 | `curl http://localhost:8080/api/health`（仅本机回环） | `"status":"UP"` |
| 登录接口 | `curl -k -X POST https://localhost/api/auth/login -H "Content-Type: application/json" -d '{"username":"admin","password":"<密码>"}'` | 返回 token |
| 前端页面 | 浏览器访问 `https://<服务器IP>`（HTTP 自动跳转 HTTPS） | 出现登录页（首次需手动信任证书） |

默认管理员账号：**admin / admin123**（全新数据库由 init.sql 初始化，请立即登录修改）。
> 当前环境的 admin 已改为随机强口令，不适用上述默认密码。

## 6. 配置项与环境变量

### 6.1 数据库与应用参数

compose 已内置默认值，通过后端工程根目录的 `.env` 文件覆盖（与 compose 文件同级，已在 `.gitignore` 中，禁止入库）。当前环境已配置真实强密码与随机 JWT 密钥：

```bash
# .env 示例（实际值请用随机串，勿提交）
DB_NAME=hanxuan_admin
DB_USERNAME=postgres
DB_PASSWORD=请改成强密码
HANXUAN_JWT_SECRET=请改成足够长的随机串
```

| 变量 | 默认值 | 用途 |
|---|---|---|
| `DB_NAME` | hanxuan_admin | 数据库名 |
| `DB_USERNAME` | postgres | 数据库用户 |
| `DB_PASSWORD` | postgres | 数据库密码 |
| `FILE_LOCAL_PATH` | /app/upload | 后端容器内上传文件目录（compose 已固定） |
| `HANXUAN_JWT_SECRET` | 内置开发默认值 | Sa-Token JWT 密钥，**生产必须覆盖** |

### 6.2 后端配置（application.yml 要点）

数据源已改为环境变量驱动，本地裸跑默认值仍为 localhost，不影响开发：

```yaml
url: jdbc:postgresql://${DB_HOST:localhost}:${DB_PORT:5432}/${DB_NAME:hanxuan_admin}
username: ${DB_USERNAME:postgres}
password: ${DB_PASSWORD:postgres}
```

JWT 密钥：

```yaml
jwt-secret-key: ${HANXUAN_JWT_SECRET:开发默认密钥}
```

> 生产环境请在 compose 的 `backend.environment` 增加 `HANXUAN_JWT_SECRET: <随机长字符串>`，或通过 `.env` 注入，切勿使用内置默认值。

### 6.3 端口修改

编辑 `docker-compose.yml` 中各服务的 `ports`，左侧为宿主机端口。例如把前端改到 8088：

```yaml
frontend:
  ports:
    - "8088:80"
```

## 7. 数据卷与备份恢复

### 7.1 数据卷

| 卷名 | 容器挂载点 | 内容 |
|---|---|---|
| `hanxuan-postgres-data` | /var/lib/postgresql/data | PostgreSQL 全部数据 |
| `hanxuan-upload-data` | /app/upload | 用户上传的文件 |

数据卷独立于容器生命周期：`docker compose down`、重建镜像、重建容器都不会删除数据。

### 7.2 数据库备份（推荐逻辑备份）

```bash
# 导出整个数据库到带时间戳的 SQL 文件
docker compose exec -T postgres \
  pg_dump -U postgres -d hanxuan_admin -F c -f /tmp/backup.dump
docker compose cp postgres:/tmp/backup.dump ./backup-$(date +%Y%m%d-%H%M%S).dump
docker compose exec postgres rm -f /tmp/backup.dump
```

也可用纯 SQL 方式（便于直接查看）：

```bash
docker compose exec -T postgres pg_dump -U postgres hanxuan_admin \
  > backup-$(date +%Y%m%d-%H%M%S).sql
```

### 7.3 数据库恢复

```bash
# 自定义格式（.dump）恢复
docker compose cp ./backup-xxxx.dump postgres:/tmp/restore.dump
docker compose exec postgres pg_restore -U postgres -d hanxuan_admin \
  --clean --if-exists /tmp/restore.dump

# 纯 SQL 恢复
docker compose exec -T postgres psql -U postgres -d hanxuan_admin < backup-xxxx.sql
```

### 7.4 备份上传文件

```bash
# 将上传卷打包到当前目录
docker run --rm -v hanxuan-upload-data:/data -v "$PWD":/backup alpine \
  tar czf /backup/upload-$(date +%Y%m%d).tar.gz -C /data .
```

### 7.5 数据卷物理备份（冷备）

停机后可直接打包 Docker 卷目录（Linux 默认路径 `/var/lib/docker/volumes/`）。生产更建议使用 7.2 的逻辑备份，可跨版本恢复。

### 7.6 定时自动备份（Windows 计划任务，已配置）

当前 Windows 部署环境已配置每日自动备份：

| 项目 | 值 |
|---|---|
| 计划任务名 | `HanxuanAdminDbBackup` |
| 执行时间 | 每日 **03:17**（错过则开机/解锁后尽快补跑，失败间隔 10 分钟重试 2 次） |
| 备份脚本 | [scripts/backup-db.ps1](file:///d:/Workspace/Ai/hanxuan-admin/scripts/backup-db.ps1) |
| 备份目录 | `E:\Documents\OneDrive\HanxuanAdminBackups`（OneDrive 同步盘，自动获得云端异机副本） |
| 文件格式 | `hanxuan_admin-yyyyMMdd-HHmmss.dump`（pg_dump 自定义格式） |
| 保留策略 | 自动清理 **14 天**前的旧备份（OneDrive 云端历史版本仍可追溯） |
| 运行日志 | `E:\Documents\OneDrive\HanxuanAdminBackups\logs\backup-*.log` |
| 运行身份 | **S4U**（无论用户是否登录/注销 Windows 均运行，无需保存密码） |
| 执行程序 | `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`（5.1） |

脚本流程：容器内 `pg_dump -F c` 导出 → `docker cp` 取回宿主机（避免 PowerShell 重定向损坏二进制）→ 校验文件大小 → 清理过期备份，全程写日志。

> 注意：备份脚本含中文，**必须以 UTF-8 with BOM 编码保存**，否则 Windows PowerShell 5.1 会按 GBK 解析导致语法错误（pwsh 7 无此问题）。修改脚本后请注意保持 BOM。

手动备份一次（任意时刻，PowerShell 5.1 / 7 均可）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "d:\Workspace\Ai\hanxuan-admin\scripts\backup-db.ps1"

# 自定义保留天数/目录
powershell -File "d:\Workspace\Ai\hanxuan-admin\scripts\backup-db.ps1" -RetainDays 30 -BackupDir "E:\db-backup"
```

计划任务管理：

```powershell
# 查看任务状态与最近一次执行结果（LastTaskResult=0 表示成功）
Get-ScheduledTask -TaskName 'HanxuanAdminDbBackup' | Get-ScheduledTaskInfo

# 立即触发一次
Start-ScheduledTask -TaskName 'HanxuanAdminDbBackup'

# 停用 / 启用 / 删除
Disable-ScheduledTask -TaskName 'HanxuanAdminDbBackup'
Enable-ScheduledTask  -TaskName 'HanxuanAdminDbBackup'
Unregister-ScheduledTask -TaskName 'HanxuanAdminDbBackup' -Confirm:$false
```

> 恢复方法见 7.3 节。备份目录已位于 OneDrive 同步盘，自动获得云端异机副本；请确认 OneDrive 客户端保持登录同步。

## 10. 健康检查与故障排查

### 10.1 启动顺序保障

compose 中 backend 通过 `dep_on: postgres condition: service_healthy` 等待数据库就绪；postgres 用 `pg_isready` 做健康检查，避免后端在数据库未就绪时启动失败。

### 10.2 常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| backend 不断重启 | 连不上数据库 | `docker compose logs backend`；确认 postgres 为 healthy；核对 DB 账号密码 |
| 页面能打开但登录失败/接口 502 | backend 未就绪或 nginx 无法解析 `backend` | `docker compose ps`；确认三容器同在 `hanxuan-net`；重启 frontend |
| 80/8080/5432 端口冲突 | 宿主机已有进程占用 | `netstat -ano | findstr :80`（Windows）/ `ss -ltnp | grep :80`（Linux）；改端口映射或停占用进程 |
| 数据未按 init.sql 初始化 | 数据卷非空 | init.sql 仅在数据目录为空（首次）时执行；已有卷不会重复执行 |
| 登录后很快掉线 | Sa-Token active-timeout 默认 30 分钟滑动会话 | 属正常策略；如需调整改 application.yml 后重建 |
| 前端更新后浏览器仍是旧页面 | 浏览器缓存 | index.html 已配置 no-cache，强刷（Ctrl+Shift+R）或确认使用的是最新镜像 |

### 10.3 手动验证链路

```bash
# 1) 后端自身
curl http://localhost:8080/api/health

# 2) 经 nginx 反代到后端（HTTPS，-k 忽略自签证书）
curl -k -X POST https://localhost/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"<管理员密码>"}'

# 3) 数据库连通
docker compose exec postgres pg_isready -U postgres
```

## 11. HTTPS（TLS）配置

前端 Nginx 负责 TLS 终结，后端与数据库仍走容器内网明文（不对外暴露）。当前环境采用**自签名证书**（适合内网/IP 访问）；如后续有公网域名，可按 11.4 节替换为受信任证书。

### 11.1 证书文件

| 项 | 值 |
|---|---|
| 宿主机目录 | `d:\Workspace\Ai\hanxuan-admin\certs\` |
| 证书 / 私钥 | `nginx.crt` / `nginx.key` |
| 容器内路径 | `/etc/nginx/certs/nginx.crt`、`/etc/nginx/certs/nginx.key`（只读挂载） |
| 有效期 | 3650 天（10 年），2026-10-11 生成，到期 2036-10 |
| SAN 覆盖 | `DNS:localhost`、`DNS:DESKTOP-64UNE1F`、`IP:127.0.0.1`、`IP:192.168.1.171` |
| 协议 | TLSv1.2 / TLSv1.3 |

`certs/` 已加入 `.gitignore`，私钥不会入库。

### 11.2 访问方式与浏览器提示

- 访问地址：`https://192.168.1.171/`（内网）或 `https://localhost/`（本机）
- HTTP `http://...` 会 **301 强制跳转** 到 HTTPS（`/health` 除外，保留明文供探测）。
- 自签名证书不被公共 CA 信任，**浏览器首次访问会提示"您的连接不是私密连接 / 不安全"**，属正常现象：
  - Chrome/Edge：点击"高级 / 继续前往"；
  - 或把 `certs/nginx.crt` 导入本机"受信任的根证书颁发机构"后警告消失。
- 更换为可信证书后该提示即消失（见 11.4）。

### 11.3 重新生成自签名证书（如 IP/主机名变更）

宿主机无 openssl，使用临时 alpine 容器生成。把命令中的 IP、主机名替换为实际值：

```powershell
cd d:\Workspace\Ai\hanxuan-admin
New-Item -ItemType Directory -Force -Path .\certs | Out-Null
docker run --rm -v "${PWD}/certs:/certs" alpine:3.20 sh -c "`
  apk add --no-cache openssl >/dev/null 2>&1 && `
  openssl req -x509 -newkey rsa:2048 -nodes `
  -keyout /certs/nginx.key -out /certs/nginx.crt -days 3650 `
  -subj '/C=CN/O=Hanxuan/CN=DESKTOP-64UNE1F' `
  -addext 'subjectAltName=DNS:localhost,DNS:DESKTOP-64UNE1F,IP:127.0.0.1,IP:192.168.1.171'"

# 证书是挂载进容器的，无需重建镜像，reload 即可生效
docker compose exec frontend nginx -s reload
```

> 多 IP / 多主机名时，在 `subjectAltName` 中继续追加 `IP:x.x.x.x`、`DNS:名称`。

### 11.4 替换为受信任证书（有公网域名时，可选）

拿到证书机构（或 Let's Encrypt）签发的 `fullchain.pem` 与 `privkey.pem` 后：

```powershell
# 覆盖挂载目录中的两个文件（文件名保持 nginx.crt / nginx.key，或同步改 nginx.conf）
Copy-Item fullchain.pem .\certs\nginx.crt -Force
Copy-Item privkey.pem  .\certs\nginx.key  -Force
docker compose exec frontend nginx -s reload
```

nginx 配置无需改动；`server_name _` 如需限定域名，可改为实际域名。

### 11.5 验证

```bash
# HTTP 301 跳转
curl -s -o /dev/null -w "%{http_code} -> %{redirect_url}\n" http://localhost/

# HTTPS 访问（-k 表示忽略自签名校验）
curl -k -s -o /dev/null -w "%{http_code}\n" https://192.168.1.171/

# 经 HTTPS 的接口
curl -k -s https://192.168.1.171/api/health

# 查看证书 SAN / 有效期
docker run --rm -v "${PWD}/certs:/certs" alpine:3.20 sh -c \
  "apk add --no-cache openssl >/dev/null 2>&1 && openssl x509 -in /certs/nginx.crt -noout -dates -ext subjectAltName"
```
